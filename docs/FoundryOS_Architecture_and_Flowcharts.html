1. Executive Architecture Overview

FoundryOS is an autonomous multi-agent operating system designed for enterprise strategy, brand positioning, market research, and automated GTM execution. Rather than treating AI as a single generic conversational bot, FoundryOS models an enterprise marketing organization as a collaborative hierarchy of autonomous specialists backed by institutional memory, deterministic tool capabilities, and human oversight.

Core Architectural Pillars

Pillar Engineering Implementation Operational Value
Autonomous Specialist Team Dedicated agents (Market Research, Competitor Intel, Chief Strategist, Funnel Architect, Assistant) with domain-specific system prompts and tool bindings. Deep specialization prevents hallucination and produces verifiable, enterprise-grade strategic briefs.
Two-Tier Agent Router Fast deterministic regex heuristic matching backed by model-based classification when queries cross boundaries. Sub-millisecond query routing for common tasks; intelligent multi-agent orchestration for complex multi-faceted prompts.
Company Brain (Institutional RAG) PostgreSQL with pgvector HNSW indexing, token-budgeted memory injection, and dynamic learning proposals. Guarantees that all agent actions, messaging, and proposals adhere to the single source of truth for brand voice and ICP.
Model Context Protocol (MCP) Standardized client/server JSON-RPC tool interface connecting external APIs (Slack, Google Drive, SEO audit, Market Intel). Clean decoupling of agent decision-making from tool execution; safe sandbox for external side effects.
HITL Steering & Governance Interactive multi-choice steering gate with 3 strategic options + custom founder input field and rejection loop. Eliminates runaway AI risks: founders approve, guide, or reject actions before brand commitments or external broadcasts occur.

3. Human-In-The-Loop (HITL) Decision Flowchart

Autonomous agents are prohibited from executing high-stakes side-effects (committing brand positioning statements, publishing GTM offers, broadcasting to external Slack channels, or modifying core institutional memory) without passing through the HITL gate.

▼ Generates Approval Proposal

▼ Synthesizes Strategic Direction Options

7. Operational Verification & Build Lifecycle

Build & Deployment Commands

Command Action Performed Output / Verification
npm run build:all Executes TypeScript compilation of the backend and runs Vite build for the client. Generates compiled backend in dist/ and optimized production bundle in public/.
npm run serve Builds the system and starts the unified Node.js HTTP server on port 3000. Hosts both REST APIs and serves the React dashboard at http://localhost:3000.
npm run dev:client Spawns Vite client development server with live Hot Module Replacement (HMR). Local dev server on http://localhost:5173 with proxy to localhost:3000.
npm test Runs 16 comprehensive Vitest test suites across routing, memory, MCP, and flows. Ensures 100% test pass rate across all services and mock providers.

Data Safety & Non-Hardcoded Secrets Compliance

FoundryOS adheres strictly to non-hardcoded secrets. All LLM keys (OPENAI_API_KEY), integration tokens (Slack bot tokens, Google Drive OAuth credentials), database passwords, and TrueForge API keys are resolved dynamically via Zod-validated environment files (src/backend/config/env.ts). If credentials are not supplied in local environments, the system automatically falls back to safe mock providers and local Ollama inference without crashing.
